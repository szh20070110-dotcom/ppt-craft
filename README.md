# 南京三日游 · 基于 AI 开发者空间的 PPT 制作实践

用 `pptx-craft` 技能的设计规范，完成一套 12 页、16:9 的南京三日游旅行提案。
最终 PPTX 中的每个文字、色块和图片都是独立可编辑对象，**不是整页截图**。

## 产物

| 文件 | 说明 |
| --- | --- |
| `南京三日游.pptx` | 12 页可编辑演示文稿，7.37 MB，16:9（1280×720） |
| `preview.html` | 12 页 1:1 HTML 预览，每页固定 1280×720，可直接截图 |
| `check.py` | 打开 PPTX 执行 10 项硬性断言，当前 10/10 通过 |

| `deck_content.py` | 12 页文案、图片映射与色板（PPT / HTML 共用） |

| `assets/` | 从技能 `photos/` 复制的实拍图（英文名，供 PPT 与 HTML 共用） |

## 一、从技能中提炼的设计规范

规范来源：`converter/SKILL.md`、`designer/SKILL.md`、`knowledge/设计经验.md`。

### 1. 画布固定 1280×720

- 幻灯片固定 `1280px × 720px`（16:9），任何内容不得越界。
- 四周 30px 安全边距，有效内容区 `1220 × 660px`。
- 背景和装饰可以铺满画布，标题、正文、图表标签必须落在安全区内。

### 2. 可读性优先于美观

- 正文不小于 `16px`，转换到 PPT 后不小于 `12pt`；本项目正文实测下限 **12pt**。
- 文字对比度 ≥ `4.5:1`，不使用 `#B5B5B5` 及更浅的灰色。
- 行距约 `1.5`，每张卡片正文不超过 2 行，单页正文不超过 14 行。
- 禁止用 `overflow-hidden`、`line-clamp`、省略号、滚动、折叠或缩小字号来隐藏核心信息。
- 标题、正文、数据、来源、卡片必须完整显示。

### 3. 宁可拆页，也要留白

- 每页先做“内容预算”：标题行数、区域比例、卡片/要点上限、最小字号、留白区间。
- 每页至少保留 **8% 的垂直缓冲**，吸收字体差异与 PPTX 转换误差。
- 内容超预算时按顺序处理：**提炼内容 → 合并重复观点 → 调整布局比例 → 移动次要材料 → 拆页**。
- 本项目的 Day1/Day2/Day3 各拆为两页，正是为了不让单页堆满。

### 4. 字体与色彩约束

- 同一份 PPT 最多使用 **2 个字体家族**：本项目标题用宋体（衬线、古典），正文用微软雅黑（无衬线、易读）。
- 标题字号 34–54pt，正文 12–17pt，相邻层级字号比例 ≥ 1.2。
- 只保留 **1 个主强调色**。本项目取“金陵古都”色板：
  - 朱砂红 `#A63A32`（强调）、墨绿 `#24483B`（主色）、鎏金 `#B8913F`（点缀）
  - 米白 `#F7F2E8` / 纸白 `#FFFDF7`（底色）、墨 `#22251F`（正文）
- 内容页不用大面积深色底，只在夜游、登高、结尾等页面用深色营造氛围。
- 每页版式不同：封面 hero、时间轴、左图右文、右图左文、顶部大图 + 卡片、深色夜游、KPI 大数字、双列清单、金句结尾。

### 5. 实景照片用法

- `object-fit: cover` 铺满目标区域，叠加 `rgba(21,36,29,.2–.58)` 压暗层，保证白字可读。
- 图片来源优先使用用户提供的本地实拍，不依赖不稳定的网络图搜。

## 二、技术路线：为什么改用 python-pptx

按技能要求先尝试 Node 转换器，结果如实记录如下：

1. **`npm install` 成功**：在 `converter/` 安装 83 个包，耗时约 2 秒，`node_modules` 就绪。
2. **Playwright Chromium 下载超时**：执行 `npx playwright install chromium`，180 秒内未完成，被终止。
3. **环境检测确认缺失**：`node scripts/cli.js check-env` 输出：
   ```
   ✅ Node.js v24.20.0
   ✅ npm 依赖已安装
   ❌ Chromium 未安装（需要 chromium-1200）
   ❌ Chromium Headless Shell 未安装（需要 chromium_headless_shell-1200）
   ```
4. **改用 python-pptx**：`python-pptx 1.0.2` + `Pillow` 安装成功，直接生成原生 PPTX。
   转换器（HTML→PPTX）依赖无头 Chromium 渲染，Chromium 不可用就无法保证转换链路的可靠性；
   python-pptx 不依赖浏览器，能稳定产出**可编辑文本框 + 可编辑图片**，满足交付要求。

> 本机虽然有 Chrome/Edge，但没有安装 Playwright 所需的 Chromium 1200 版本；
> Chrome 仅用于 `audit_layout.py` 对 HTML 预览做越界/重叠审计，不参与 PPTX 生成。

## 四、素材说明（如实记录）

技能 `photos/` 目录存在文件名与画面不符、跨景点重复的情况：

- `南京玄武湖_*.jpg`、`南京紫金山_*.jpg` 与 `南京夫子庙秦淮河夜景_*.jpg` 四组文件 **MD5 完全相同**。
- 其中 `_0`、`_1` 实拍主体是**鸡鸣寺**（黄色寺墙、樱花），不是玄武湖水面，也不是紫金山山林。
- `_2` 是夫子庙“天下文枢”牌坊（白天），`_3` 是夫子庙/秦淮河画面。

处理方式：

- 第 7 页使用鸡鸣寺实拍图，并在页面图片下方如实标注 **“实拍 · 鸡鸣寺（玄武湖南岸）”**，不冒充玄武湖湖景。
- 第 8 页使用 `南京中山陵_1.jpg`（紫金山南麓中山陵），标注为紫金山南麓。
- README 与页面注记均保留这一事实，避免把错标素材当作真实景点照片使用。

## 六、复现

```bash
pip install -r requirements.txt
python build_pptx.py      # 生成 南京三日游.pptx
python build_preview.py   # 生成 preview.html
python check.py           # 10 项断言，期望 10/10
python audit_layout.py    # 可选：需要本机 Chrome
```

仅重新生成 PPTX 时执行 `python build_pptx.py` 即可；文案与图片映射统一在 `deck_content.py`。
